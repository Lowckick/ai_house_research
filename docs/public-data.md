# Відкриті набори реальних показників (UCI)

Три відкриті набори з UCI Machine Learning Repository (ліцензія CC BY 4.0) пройшли той самий
шлях, що й живі датчики: валідацію, рекомендації моделі в тіньовому режимі, калібрування
симулятора. Потім відкалібровані параметри стали варіантами будинку для перевірки моделі.
Це **чужі вимірювання**, а не власні датчики автора; у кожному наборі невідомо, як працювало
обладнання, тож аналізуються умови й рекомендації, а не ефект їх виконання.

| Набір | Що це | Джерело |
| --- | --- | --- |
| SML2010 | будинок у Валенсії (Іспанія), 50 днів, кожні 15 хв: температура, CO₂, вологість їдальні, вуличний датчик | Romeu-Guallart, Zamora-Martinez, 2014 · [UCI 274](https://archive.ics.uci.edu/dataset/274/sml2010) |
| Appliances | енергоефективний будинок у Бельгії, 137 днів, кожні 10 хв: температура й вологість 8 кімнат (середнє), погода аеропорту | Candanedo, Feldheim, Deramaix, Energy and Buildings 140 (2017) · [UCI 374](https://archive.ics.uci.edu/dataset/374/appliances+energy+prediction) |
| Occupancy | офіс у Монсі (Бельгія), 16 днів, щохвилини: температура, вологість, CO₂, присутність (так/ні за фото) | Candanedo, Feldheim, Energy and Buildings 112 (2016) · [UCI 357](https://archive.ics.uci.edu/dataset/357/occupancy+detection) |

```bash
python main.py public-data --dataset sml2010 --input <розпакований-архів> --output /tmp/sml2010.json
python main.py adapt --houses uci_sml2010 uci_appliances uci_occupancy --output-dir data/user/training/adaptation-01
```

Звіти: [`results/public-sml2010.json`](results/public-sml2010.json),
[`results/public-appliances.json`](results/public-appliances.json),
[`results/public-occupancy.json`](results/public-occupancy.json); перевірка моделі —
у [`results/adaptation-2026-11-18.json`](results/adaptation-2026-11-18.json) (будинки `uci_*`).

## 1. Дані та тіньовий режим

| | SML2010 | Appliances | Occupancy |
| --- | ---: | ---: | ---: |

| Температура, мін / медіана / макс, °C | 11.4 / 20.5 / 28.9 | 16.0 / 20.6 / 26.1 | 19.0 / 20.7 / 24.4 |
| Вологість, медіана, % | 42.8 | 40.6 | 27.3 |
| CO₂, медіана / макс, ppm | 205 / 594 * | — | 565 / 2 077 |
| Час у комфорті: температура / вологість / CO₂ | 59 % / 81 % / — | 84 % / 96 % / — | 100 % / 9 % / 85 % |
| Початків тривог | 13 температура, 9 вологість | 0 | 31 критична й 59 попереджень CO₂, 38 вологість |
| Мережа змінила рішення контролера: опалення / вентиляція | 13.1 % / 0 % | 2.6 % / 0 % | 2.3 % / 8.0 % |

\* CO₂ у SML2010 нижчий за вуличні ~410 ppm, тобто датчик мав зсув калібрування; для аналізу CO₂ цей набір непридатний.

Рекомендації відповідали потрібним пристроєм на всі виходи за комфорт (2 483, 3 839 і 21 872).
**Недолік, який виявив тіньовий режим:** у 64–88 % рішень мережа вмикала робота-пилососа, хоча
забруднення в жодному наборі не вимірювалось і валідатор підставляв 0. Тобто корекції за
невиміряними величинами ненадійні: їх варто вимикати для пристроїв, чиї датчики відсутні.

| Набір | Параметр | Оцінка | Типове значення симулятора | Якість |

| Appliances | тепловтрати, частка/год | 0.0073 ± 0.0002 | ≈0.093 | R² 0.05: будинок опалювався, оцінка наближена |
| Occupancy | генерація CO₂ за присутності, ppm/год | 90.5 ± 4.3 | 20 на людину | прийнято; присутність записано як так/ні |
| Occupancy | природний повітрообмін, частка/год | 0.060 ± 0.006 | 0 | R² 0.21, прийнято |

Обмін вологою в жодному наборі значуще не оцінився; тепловтрати офісу — теж (немає вуличних даних).

## 3. Модель на відкаліброваних будинках

Та сама процедура, що в [adaptation.md](adaptation.md): пороги перепідібрано на validation,
мережу перенавчено, оцінка на test (seed 20000 / 31000, по 20 сценаріїв).

| Будинок | Пороги типові | Пороги перепідібрані | Мережа з типового | Мережа перенавчена |
| --- | ---: | ---: | ---: | ---: |
| SML2010 | 165.2 / 167.0 | 172.4 / 175.7 | 182.2 / 187.8 | 186.3 / 190.1 |
| Appliances | 234.1 / 228.9 | 238.0 / 233.2 | 245.0 / 241.5 | 247.1 / 242.6 |
| Occupancy | 128.5 / 129.2 | 136.2 / 136.0 | 144.4 / 143.2 | 146.6 / 147.5 |

Перенавчена мережа мінус перепідібрані пороги:

| Будинок | Винагорода | Комфорт, в.п. | Енергія, кВт·год | Краще у сценаріях | Більше небезпечних кроків |
| --- | ---: | ---: | ---: | ---: | ---: |
| SML2010 | +13.8 / +14.5 | +1.67 / +1.65 | +0.44 / −0.23 | 38 / 40 | 0 |
| Appliances | +9.1 / +9.3 | +1.06 / +1.11 | +0.19 / +0.27 | 39 / 40 | 0 |
| Occupancy | +10.4 / +11.4 | +1.11 / +1.20 | −1.10 / −1.87 | 34 / 40 | 5 з 40 |

- Мережа краща за перепідібрані правила на кожному відкаліброваному будинку, у 111 зі 120 сценаріїв.
- В енергоефективному будинку Appliances мережа з типового будинку перегрівала (19.4 кВт·год
  проти 17.5 у правил на наборі 20000); перенавчання повернуло споживання до 17.7 кВт·год.
- В офісі з реалістичною генерацією CO₂ небезпечних кроків приблизно стільки ж, скільки в
  правил (18.65 проти 18.70 і 18.30 проти 18.20 за добу), але в 5 сценаріях із 40 їх більше.
  Там, де CO₂ росте швидко, перевага мережі в комфорті не супроводжується перевагою в безпеці.
